## Working rules for this tree

- **Several sessions share this tree and its build directory.** Check for running `cmake`, `cl` and `test_*` processes before building. Copy a test exe elsewhere before running it, with `dist\Release` on `PATH`, so you do not block another session's linker.
- **Before deploying**, run `scripts\services.ps1 build`. The Go binaries in `dist\services` do not rebuild with the C++ and were hours stale this time.
- **Do not deploy any package or `worldd.exe` built before 20:46 on 31 October**, including `build/gm-deploy`. Those can crash in `load_area` at startup.
- **Stale objects:** garbage values or odd crashes may be stale objects, not bugs. `scripts\build.ps1 -FreshObjects -Target ALL_BUILD -Jobs 6` compiles our own code again without touching the dependencies; the script now retries C1083 lock errors by itself. Do not save headers while a build runs.
- **Rollback:** the previous programs are in `C:\SandalCore\dist.prev`, and the next `sandalctl update` deletes them. The database dump taken before this update is in `C:\SandalCore\backups`. Migrations 0019 and 0020 only add tables.
